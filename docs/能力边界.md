# 管线能力边界(2026-09-29 定稿)

> 本文回答三个问题:**现在支持什么、明确不支持什么、未来怎么扩展**。
> 边界是声明,不是遗漏;每一项不支持都有扩展路径。新会话/新项目以此为准,不要凭感觉夸大或贬低管线能力。

## 一、支持矩阵(如实版)

| 层级 | 品类/形态 | 现状 |
|---|---|---|
| **设计支撑齐全** | 消除、合成、放置、跑酷、点击、轻益智(单机休闲) | 手册+工具+验收全对齐,当前验证范围 |
| **架构可用、专项手册未展开** | 剧情叙事类(立绘/对话/CG 资产线)、强动作类(手感调参)、模拟经营(经济数值)、Roguelike(程序化关卡) | 五步工作流与验收框架通用;做成成品需按品类手册契约补专项手册(见下) |
| **明确不支持** | 3D、强联网/实时对战、多端同时发行 | 见第二节,均有扩展路径 |

## 二、明确裁剪项(按当前定位,非遗漏)

| 裁剪项 | 理由 | 扩展路径 |
|---|---|---|
| 3D 游戏 | 引擎上下文与资产线全是 2D | 新引擎适配器 + 3D 资产线重写(GameFactory-3A 可再参考) |
| 强联网/实时对战 | 管线只做客户端;服务器/帧同步/反作弊是另一条生产线 | 先声明,需要时立项"服务端管线" |
| 重度内购经济 | 合规可行,但无数值设计手册 | 补经济系统设计手册后再宣称支持 |
| 多语言 | 国内单语言 | 文案表化即可起步 |
| 多端同时发行 | 平台适配器仅微信一个实例 | 按平台适配层契约加实例(交付手册+验收附录+adapter) |

弱联网(云存档/云排行榜)**不在此列**:经平台适配层支持,微信侧方案见 `adapters/cocos/组件库/wechat-adapter/开放数据域.md`。

## 三、三个适配维度(扩展 = 加一份适配物,核心手册零改动)

| 维度 | 位置 | 首个实例 | 加新实例 = |
|---|---|---|---|
| 引擎 | `adapters/cocos/` | Cocos Creator 3.8.8 | 引擎操作手册 + API 上下文 + 工具链接入 |
| 平台 | `adapters/platform/<平台>/` | 微信小游戏 | 交付手册 + 验收附录 + 平台适配层实现 |
| 品类 | `manuals/genres/<品类>.md` | 暂无(休闲约定内嵌通用手册) | 按**品类手册契约**写一册(见 `manuals/genres/README.md`) |

## 四、品类扩展承诺

**用户要求(2026-09-29):管线未来必须支持休闲之外的更多 2D 品类。** 依据三维架构,这个承诺的兑现物是:

1. **品类手册**(知识):按契约补该品类的 DSL 字段、资产类型扩展、内容量基线、验收补充——不新建就能开工,但定稿后 M2/M3/验收全套工具自动跟上。
2. **品类资产工具**(代码):评分器/生成器按新品类扩展检查器(如叙事类的立绘一致性、动作类的骨骼帧)。
3. **实战校准**:该品类首跑后修订阈值与清单。

扩一个品类的成本 ≈ 一册手册 + 若干检查器,**不动核心手册、不动引擎/平台适配层**——这就是三维架构存在的意义。

## 五、已知未校准项(如实)

- 全部质检阈值(调色板 ΔE 16、帧跳变 24、包体预算分配)为初始拍定值,**0 款实战校准**。
- 组件库八件套:settings/reddot 已实现,其余为接口约定。
- 微信好友排行榜开放数据域方案已文档化,未实测。
- 手册中标注"框架版"的章节(关卡量产/交付)未经实战修订。
