# 架构决策记录

> 这些决策已经用户确认,不要推翻;要改请用户主动重议。每条附理由,防止将来"为什么当时这么定"失传。

## 1. 分层:手册为核心,工具为双手,质检为卡尺;不自研 Agent 运行时

- `manuals/`(AI 读的工作手册)是核心;`tools/` + `adapters/`(可执行能力)是双手;验收清单与评分器是卡尺。
- **不自研 harness**:用现成编程智能体(Claude Code / ZCode 等)当运行时。
- 理由:GameFactory-3A 验证了"手册+工具即可驱动 AI 承担生产线";运行时是红海且非本项目价值点。

## 2. 引擎/平台/品类三维适配,核心手册零依赖

- 管线核心(manuals/、tools/、契约)不依赖任何引擎,**也不依赖任何分发平台、不锁定品类**。三个适配维度:引擎 adapter(`adapters/cocos/`,首个 = Cocos Creator 3.8.8)、平台 adapter(`adapters/platform/<平台>/`,首个 = 微信小游戏:交付手册 + 验收附录)、**品类手册**(`manuals/genres/<品类>.md`,知识模块:DSL 字段/资产类型扩展/内容量基线/验收补充;首个品类手册随 001 定稿)。
- 平台 adapter 的职责:该平台的能力清单(登录/广告/分享/流量位)、包体与分发约束、性能红线、上架合规、SDK 适配实现(组件库的 `<platform>-adapter/`)。
- **2026-09-29 用户澄清:目标是 2D 游戏管线,不只是微信小游戏**——微信是第一个平台实例,不是管线的定义。
- **2026-09-29 用户提醒:未来必须支持休闲之外的更多 2D 品类**——据此把品类立为第三个适配维度(此前品类约定内嵌通用手册);扩品类 = 写一册品类手册 + 扩展检查器,核心零改动。
- 理由:引擎、平台、品类都会扩展(Unity/Laya/Steam/原生手游;叙事/动作/经营…),只动对应适配物,不动手册主体。

## 3. 两仓分离(用户明确纠正过,务必遵守)

- 本仓库 = 管线正本(manuals/、tools/、adapters/);每个游戏独立建仓,只放该游戏自己的东西。
- 游戏工程根目录一个 `AGENTS.md` 指针接进管线;商业化组件库正本在 `adapters/cocos/`,游戏工程里放副本。
- 理由:管线要复用于 N 款游戏,混仓会让"正本"污染;每个游戏仓保持自包含、可整体交付。

## 4. 不做 UI

- 界面 = 聊天窗口 + Cocos 编辑器(经 MCP 实时可视)+ 生成的素材 + 游戏本体;仪表盘等以后再说。
- 理由:界面开发会吃掉管线本身的开发时间;MCP 已让编辑器天然可视化。

## 5. 产品化暂缓

- 先用 001 项目跑出"快多少/省多少"的数据,再决定商业化路径(内部成本优势 > 组件 API > 开源 > SaaS)。
- 理由:没有数据的商业化决策是猜;内部使用先验证价值。

## 6. 游戏框架层:引擎通用正本 + 品类玩法运行时(2026-09-29,001 立项时用户确认)

- 组件库八件套只覆盖**商业化系统层**,不含让游戏跑起来的骨架。补两层,归位三维架构:
  - **引擎通用框架** `adapters/cocos/框架/`(引擎维度正本):场景/流程管理、机制契约事件总线、音频管理、对象池、资源加载、存档封装(ISaveStore 的平台实现挂平台适配层)、UI 基类。所有 Cocos 游戏放副本复用,与组件库同分发规则。
  - **品类玩法运行时**(品类维度,随品类手册诞生):品类核心玩法的解释器——三消棋盘引擎(格子/交换/消除/级联/死局检测/洗牌)= 关卡 DSL 的解释器。纯 TS 逻辑核纪律,Node 可测,与组件库 logic 同规。
- 建法:**不预先造大而全**,随 001 M1 白盒按需建最小可用正本,渐进扩展;需要哪块建哪块。
- 理由:用户在 001 立项确认时指出"业务框架不需要吗"——缺这层游戏跑不起来;M3"游戏代码只写解释器"的解释器此前悬空;按维度归位后不污染核心手册。

## 7. 001 目标平台四波次(2026-09-29,用户确认)

- 001 目标平台:**微信小游戏(首发)→ 网页版(波次2)→ 抖音小游戏(波次3)→ TapTap(波次4)**。
- 每波 = 新增一份平台适配物(交付手册 + 验收附录 + 平台适配层实现);**M1–M4(白盒/资产/关卡/组件)平台无关,不等任何平台**。
- 波次设计:网页零 SDK(存档走 localStorage、无小游戏广告),最便宜地验证"换平台=换适配器";抖音与 wx 同构度高,适配层平移;TapTap 原生构建,变现生态非小游戏广告体系,届时单独核实再定。
- 理由:多平台是用户明确目标;一次性四平台会拖垮首跑的校准节奏,波次化让"加平台=加适配物"的架构承诺逐个被实战验证。
