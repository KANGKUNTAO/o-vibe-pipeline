# 关卡量产手册(M3)— 关卡 DSL → 批量生成 → 数值校验

> 「可玩切片」与「成品」的分水岭:手工摆 5 关叫 demo,批量产 40+ 关且数值受控才叫成品。本手册定义内容量产线的规范。  
> 状态:框架版(2026-09-29);DSL 具体字段在 001 立项时按品类定稿。

## 原则

1. **关卡是数据,不是代码**:关卡内容全部进 `assets/levels/*.json`(或策划表),游戏代码只写"解释器"。
2. **规范写成代码**:每批关卡生成后必须过校验器(下节),校验不过不入库。
3. **难度是曲线,不是感觉**:难度参数显式进 DSL,校验器检查曲线单调性与梯度密度。

## 关卡 DSL 框架(品类字段立项时定稿)

以消除类为示例骨架,其他品类替换"棋盘/目标"段:

```json
{
  "id": "level-001",
  "chapter": 1,
  "board": { "cols": 7, "rows": 7, "cellAssetPrefix": "g001-spr-gem" },
  "rules": { "moves": 20, "objective": { "type": "collect", "targets": [{ "id": "gem-red", "count": 30 }] } },
  "elements": ["gem-red", "gem-blue", "gem-green"],
  "specials": [],
  "difficulty": { "intended": 1.0, "params": { "deadlockRate": 0.05 } },
  "meta": { "starThresholds": [1000, 2000, 3000], "genSource": "template-v1", "genDate": "…" }
}
```

## 批量生成策略(按优先级)

1. **模板+参数扫描**:固定骨架,扫描步数/目标/元素数/特殊元素 → 章节内梯度。
2. **约束随机**:随机填充 + 校验器过滤(不达标重摇)。
3. **手写特调关**:每章 1-2 关手工精调当"记忆点",其余批量。

生成来源写进关卡 `meta.genSource`,可复现、可回溯。

## 校验器规范(已实现:`tools/levelcheck/`;三消 DSL 见 `manuals/genres/match-3.md`)

每批关卡入库前必须全绿:

| 检查        | 内容                                            |
| --------- | --------------------------------------------- |
| 结构校验      | JSON schema:字段齐、类型对、引用的元素 ID 存在于资产清单 manifest |
| 可解性(品类相关) | 消除类:模拟求解器确认给定步数内目标可达(至少一个解);其他品类立项时定义         |
| 难度曲线      | 章内难度非暴增,章间递进;deadlock 率在阈值内                   |
| 数值表交叉     | 关卡奖励产出 × 关卡数 与 经济系统消耗 数量级匹配(防通胀/通缩);**v2 待经济表存在后接入**(品类手册 §7.6)           |

## 量产节奏(与五步工作流衔接)

- 白盒阶段:手写 3-5 关验证解释器,不批量。
- 内容完成阶段:按立项卡目标(如 40 关 = 4 章 × 10 关)批量生成 → 校验 → 抽查真机通关(首/中/尾各 2 关)。
- 产出物:`assets/levels/` 全量关卡 + 校验器报告(存 `evidence/关卡校验/`)。
