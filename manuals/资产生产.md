# 资产生产手册(M2)— 2D 资产生成 + 确定性质检

> 五步工作流第 4 步(资产精修)的展开。目标:把 manifest 里的占位资产逐件换成达标成品,**每件有出处、过评分、可追溯**。
> 行业难题背景:2D 生成的一致性(帧间/全局风格)未被工具解决 → 本管线的差异化就是把质检做成**确定性评分器**,不靠人眼。
> 状态:协议版(2026-09-29,GameFactory asset_qa 深度对齐);评分器实现于 `tools/评分器/`,随 001 落地。

## 2D 资产分类与规格约定

| 类别 | 规格 | 格式 | 质检重点 |
|---|---|---|---|
| 立绘/精灵 spr | 2 的幂尺寸,透明底,中心锚点 | PNG | 剪影完整、调色板一致 |
| 动画帧 eff/spr | 帧数固定,同尺寸,同锚点 | PNG 序列 | **帧间一致性**(本手册核心) |
| tileset | 网格对齐(64/128),可平铺 | PNG | 平铺无缝、格线对齐 |
| UI | 九宫格切片标注,标准控件尺寸 | PNG | 可拉伸、文字区留白 |
| 音效/音乐 audio | 音效 ≤200KB,BGM 循环无缝 | MP3/OGG | 时长、采样率、响度 |
| 字体 font | 中文子集化 | TTF/BMFont | 覆盖游戏全部文案字符 |

具体数值在立项卡定,写进 manifest 的"规格"列,评分器按 manifest 检查。

## 生成前规划(先规划后生成,逐件记录)

每件资产在第一次生成**前**,把以下字段写进 manifest 的生成记录——它们同时就是生成提示词的原料:

| 字段 | 例 |
|---|---|
| 角色与用途 | 玩家可控主角色 / 结算界面背景 |
| 风格与参考 | 立项卡参考图 + 全局风格锚点资产 |
| 视角/构图 | 正面 / 45° / 全身居中 / 透明底 |
| 下游用途 | 挂哪个节点、动几帧、要不要九宫格 |
| 剪影与关键特征 | 圆润无尖角、主色红、头顶绿叶 |
| 规格 | 尺寸/帧数/锚点(来自 manifest 规格列) |
| 验收标准 | 评分器阈值 + 人工判定要点 |

**禁止**拿着模糊的想法直接生成再反复返工。先建立**风格锚点资产**(第一件达标的资产),后续资产以它为调色板与风格基准——这是对冲"风格全局一致性"难题的第一手段。

## 每件资产的生产流程(状态机)

```
占位 → 生成中 → [评分器] 达标 → 已入库
                ↘ 不达标(重试 N 次)→ 需授权(换素材源)→ 已入库(记出处+许可证)
                ↘ 源也没有 → 缺口(如实上报用户,不许劣质充数)
```

1. **生成**:按 manifest 的 ID、规格与生成前规划字段生成。后端可替换(见下节);付费后端先走付费审批(见"出处与许可证")。生成记录(ID、后端、提示词、日期、重试次数)写入 manifest。
2. **质检**:跑 `tools/评分器/`(见下节)。达标线在立项卡定。
3. **入库**:素材文件进 `assets/art/`(按类别分目录,文件名=资产 ID),manifest 状态改"已入库"。
4. **回归**:该资产参与的玩法流程重跑(引擎操作手册),确认尺寸/锚点/遮挡/动画没被换坏。

## 后端可替换契约

同一资产的不同生成后端(本地模型 / 云端 API / 素材源)**共享同一输出契约**:尺寸、格式、命名、目录、评分器入口完全一致。换后端只换"生成"一步,质检与入库流程不变。

- 后端信息记录进 manifest(工具名、模型/参数、日期)——这是"出处留痕"的一部分。
- 产物不达标:先换提示词/参数重试 → 再换后端 → 最后走授权来源;每次尝试都留记录,不许静默换道。

## 评分器规范(确定性,可执行——规范写成代码)

三个检查器,输入输出固定,AI 只消费结论:

| 检查器 | 输入 | 输出 | 默认口径 |
|---|---|---|---|
| `调色板一致性` | 资产图 + 参考图(立项卡指定) | 每图主色与参考色板的 Lab 距离分,超阈清单 | 平均距离 ≤ 阈值 T(立项定,先松后紧) |
| `帧间一致性` | 帧序列目录 | 相邻帧感知哈希距离曲线 + 跳变帧清单 | 相邻帧距离 ≤ 阈值;序列尺寸/锚点一致 |
| `尺寸规格` | manifest | 不合规清单(尺寸/格式/透明度/命名) | 零容忍,必须全绿 |

评分器输出 JSON + 人类可读摘要,存 `evidence/资产质检/`。**评分器不代替游戏内回归**(评分器过≠游戏里没问题)。

**已实现**(`tools/scorer/`,2026-09-29):尺寸规格(命名=ID、PNG 格式、尺寸/2 的幂、透明底)+ 调色板一致性(Lab ΔE,`--ref` 锚点图取参考色板;fail 退出码 1 可挂 CI)。**帧间一致性待建**。

```bash
# 游戏工程根目录:占位生成 → 评分
python <PIPELINE>/tools/placeholder/gen.py --manifest docs/资产清单.md
python <PIPELINE>/tools/scorer/run.py --manifest docs/资产清单.md \
    --assets-root assets/art --ref assets/art/spr/<锚点ID>.png
```

### 实现蓝图(`tools/` 三层契约,平移自 GameFactory develop_harness)

评分器/校验器/资产生成脚本统一按三层实现,依赖只准向下:

```
服务对接层(只管调一个生成/检测服务,不懂任务与路径)
  → 算子层(任务→产物+指标,纯函数,不懂具体模型与 CLI)
    → 运行层(批量跑+评分+汇总,唯一含 CLI 与路径注册的地方)
```

- 输出路径只在运行层**单点注册**,其余层禁止出现字面输出路径。
- 每个算子配 stub 冒烟:无 GPU、无网、毫秒级验证产物布局正确。
- 评测/校验只读已有产物,**禁止**加载生成模型。
- 反模式:算子里写 CLI 参数解析、算子自建服务客户端、路径硬编码、`except: pass` 吞错。

## 出处与许可证(红线)

- 每件"已入库"资产必须填 manifest 的"出处"与"许可证"两列:生成=工具名+提示词日期;素材源=URL+许可证名。
- 只用明确可商用的来源;登录墙后的内容不许爬。
- 许可证禁商用的工具链同理不引入(DaxianLee/cocos-mcp-server 即因此未采用):引入任何工具前查 LICENSE,只收 MIT/Apache/可商用。

### 付费审批协议(用付费生成/素材服务前,四步)

1. **暂停**当前生成流程。
2. 给出该服务的购买/API key 页面。
3. 报出预估费用:**含重试量**(件数 × 单价 × 预计重试次数)。
4. 等用户明确答复并提供密钥(进环境变量,不入库)——答复前不调用。

免费额度内的服务免请示,但用量照记 manifest。
