# 品类手册契约 — 如何为一个新的 2D 品类建立支撑

> 品类是管线的第三个适配维度(引擎/平台/品类,见 `docs/能力边界.md`)。
> 为新品类立支撑 = 按本契约写一册 `<品类>.md` 放本目录,**核心手册零改动**;M2/M3/验收的扩展点都挂在手册定义的字段上。

## 一册品类手册必须回答(七项,缺一不算定稿)

1. **核心循环模板**:该品类的玩家动词、一局结构、爽点机制——喂给 M1《玩法切片》设计八问的第 2/8 问。
2. **章节/关卡 DSL 字段定稿**:该品类一关的完整数据结构(JSON 骨架)——喂给 M3《关卡量产》,校验器的结构检查依此实现;可解性检查的品类算法定义也在此。
3. **资产类型扩展**:该品类特有的资产类别、规格 token、评分器扩展点(如叙事类的立绘一致性、动作类的骨骼帧序列)——喂给 M2 评分器。
4. **内容量基线建议**:该品类"能上线"的及格线——喂给验收清单第 2 条。
5. **八件套裁剪建议**:哪些组件标配、哪些裁剪、哪些要替换成品类特供(如放置类的离线收益组件)。
6. **专项验收补充**:通用 8 条之外该品类必查的条目(如动作类的操作延迟、经营类的离线结算正确性)。
7. **参考标杆 2-3 款**:研习节奏/数值/引导,不抄美术与名字。
