# 品类手册 — 三消 Match-3(2026-09-29 随 001 · GemForest 定稿)

> 本册按 `manuals/genres/README.md` 七项契约编写,是管线**品类维度的首个实例**。
> 核心手册(M1–M5 通用流程)零改动;M2 评分器、M3 校验器的品类扩展点全部挂在本册定义的字段上。
> 001 的棋盘引擎 = 本册 DSL 的解释器(架构决策 6:品类玩法运行时)。

## 1. 核心循环模板

- **玩家动词**:交换(相邻两格)、观察(找可消组合)、等待(级联结算)
- **一局结构**:进入关卡(目标/步数展示)→ 开局(布局呈现)→ 循环[交换 → 消除 → 下落补充 → 级联 → 目标/步数更新]→ 结算(胜:星档/奖励;负:失败弹窗→补步广告/重试)
- **爽点机制**:级联连锁(一次交换多波消除)、特殊件组合(条纹+炸弹等)、擦边过关(最后一步达成目标)、收集进度条将满未满
- 一局时长基线:**90–180 秒/关**(超过 3 分钟说明难度超标,校验器难度曲线兜底)

## 2. 章节/关卡 DSL 字段定稿(M3 校验器依此实现)

### JSON 骨架(定稿)

```json
{
  "id": "g001-level-001",
  "chapter": 1,
  "index": 1,
  "board": { "cols": 7, "rows": 7 },
  "start": "random",
  "rules": {
    "moves": 20,
    "objective": { "type": "collect", "targets": [ { "id": "gem-red", "count": 30 } ] }
  },
  "gemTypes": ["gem-red", "gem-blue", "gem-green", "gem-yellow", "gem-purple"],
  "blockers": [ { "type": "ice", "cell": [3, 3], "hp": 2 } ],
  "mechanics": [],
  "difficulty": { "intended": 1.0, "params": { "deadlockRate": 0.05 } },
  "meta": { "starThresholds": [1000, 2000, 3000], "genSource": "template-v1", "genDate": "2026-09-29" }
}
```

### 字段表(类型与约束即校验规则)

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | string | 全库唯一;格式 `g001-level-NNN`(三位零填) |
| `chapter` / `index` | int | chapter 1..4;index 1..10(章内) |
| `board.cols` / `rows` | int | 6..9 |
| `start` | `"random"` 或 int[rows][cols] | 0=空格,1..N 对应 `gemTypes` 序号;特调关用显式矩阵 |
| `rules.moves` | int | 10..40 |
| `rules.objective.type` | enum | `collect`(收集)或 `score`(达到分数) |
| `objective.targets` | 数组 | collect 时 1..3 项;`id` ∈ gemTypes 或障碍产出件;`count` ≥ 1 |
| `gemTypes` | string[] | 4..6 个;命名 `gem-<词>`;引用的资产 ID 必须存在于资产清单 |
| `blockers` | 数组 | 0..N;`type` ∈ {`ice`(可消除,带 hp), `stone`(不可消,占格)};`cell` 在棋盘内且不重复;`hp` ≥ 1 |
| `mechanics` | string[] | 本关启用的特殊件 ∈ {`striped`,`bomb`,`rainbow`};按章节引入表(下)递进 |
| `difficulty.intended` | float | ≥ 0.1;**章内单调不减(容差 0.15),章间首关 ≥ 上章末关 − 0.1** |
| `difficulty.params.deadlockRate` | float | 0..0.15 |
| `meta.starThresholds` | int[3] | 严格递增 |
| `meta.genSource` / `genDate` | string | 生成溯源,可复现(批量生成策略见关卡量产手册) |

### 章节引入表(001 用;机制只增不减)

| 章 | 新引入 | 说明 |
|---|---|---|
| 1 | 基础三连 + collect 目标 | 教学关(1-1/1-2)引导交换 |
| 2 | `striped` 条纹(4 连生成) | 线性消除 |
| 3 | `ice` 障碍 + `bomb` 炸弹(L/T 型生成) | 双新件不进同一章的 1-2 关 |
| 4 | `stone` + `rainbow`(5 连生成) | 毕业章,综合考验 |

### 可解性算法定义(品类相关检查,校验器实现依此)

1. **非死局检查**(所有关必过):棋盘存在至少一个交换可产生 ≥3 匹配。`start=random` 由生成器保证;显式布局关校验器全查。
2. **目标可达**:显式布局特调关跑完整求解器(交换 DFS + 剪枝;约束 moves ≤ 40、棋盘 ≤ 9×9,设时限);随机关要求 `meta` 附生成时求解通过的记录,校验器抽查复算。
3. 校验器报告:`levelsChecked / failList / 实测deadlockRate / 难度曲线结论`,存 `evidence/关卡校验/`。

## 4. 内容量基线建议(验收清单第 2 条品类实例)

- **及格线:40 关(4 章 × 10 关)/ 宝石 5-6 种 / 障碍 2 种 / 特殊件 3 种 / 广告位 2 个(补步、道具)**
- 依据:行业三消上线初期体量惯例 + 每章引入一个新机制的节奏(见章节引入表);少于 20 关不构成"成品"验证强度。

## 5. 八件套裁剪建议(001 已按此定稿)

- **标配**:signin、adslot(补步+道具两广告位)、settings、reddot、achievement、share
- **品类用法**:shop = 金币→道具软货币兑换(纯广告模式无付费货币);leaderboard = 分数上报 + 本地最高分,**好友榜渲染为实验项**(开放数据域首跑实测,失败可裁)
- **无需品类特供组件**:三消不涉及离线收益/建造队列等系统驱动需求;玩法运行时归品类维度(下节),不算第八件套的扩展

## 6. 玩法运行时职责边界(架构决策 6 的品类实例)

| 层 | 职责 | 归属 |
|---|---|---|
| 棋盘引擎 | 格子模型、交换合法性、匹配检测(≥3 连)、级联下落与补充、死局检测与洗牌、目标计数、分数/星档结算 | **品类运行时正本**(随 001 建,纯 TS 逻辑核,Node 可测) |
| 引擎框架 | 事件总线、场景/流程流、存档封装、音频、对象池 | 引擎正本 `adapters/cocos/框架/` |
| 游戏仓 | 组装:白盒场景、表现层、关卡解释器接入、配置 | gemforest 仓 |

硬规矩:表现层只消费机制信号(消除组/级联数/目标进度),**不做二次玩法判定**;所有可点元素映射机制契约命令。

## 7. 专项验收补充(通用 8 条 + 平台附录之外,本品类必查)

1. **全量关卡过校验器**:结构/非死局/难度曲线/星档全绿,报告入 `evidence/关卡校验/`
2. **抽查通关**:第 1/2、19/20、39/40 关真机通关录屏(首/中/尾)
3. **死局处理**:洗牌必须存在且收敛,死局提示可见
4. **广告挂钩实测**:失败弹窗 → 补步(+5 步)链路真机走通,含激励视频无填充的降级路径
5. **手感**:交换输入到视觉反馈 < 100ms;级联结算节奏可感知(白盒录屏标注时间戳)
6. **经济初检**:40 关金币总产出 vs 商店道具消耗数量级匹配(防通胀/通缩)——关卡校验器"数值表交叉"项的三消实例
