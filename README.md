# vibe-pipeline

**一条「2D 微信小游戏从需求直达成品」的 AI 生产管线。** 不是做某一款游戏,是做管线本身:AI(编程智能体)按这里的手册和工具,把一条游戏需求一路做成可提审的微信小游戏成品。

- 引擎:Cocos Creator 3.8.8(2D)· 平台:微信小游戏 · 品类:休闲(消除/合成/放置/跑酷)
- 运行时:不自研 Agent 框架,用现成编程智能体(Claude Code / ZCode 等)当执行者,靠手册约束行为

## 仓库结构

| 目录                | 放什么                                                       |
| ----------------- | --------------------------------------------------------- |
| `manuals/`             | 给 AI 读的工作手册。**`manuals/总入口.md` 是一切任务的起点**,`manuals/验收清单.md` 是成品的北极星 |
| `tools/`             | 可执行工具:资产质检评分器、包体统计、关卡校验等(规范写成代码,不靠人眼)                     |
| `adapters/cocos/` | Cocos 适配层:引擎操作手册(cocos MCP 用法)、商业化八件套组件库正本                |
| `docs/`           | 管线自身的设计沉淀:路线图、架构决策                                        |

## 怎么用(给一款新游戏接入管线)

1. 新建独立游戏工程仓(如 `E:\AiProject\Vibe-OFrame`),里面**只放这款游戏自己的东西**。
2. 在游戏工程根目录放一个 `AGENTS.md`,内容一句话:`接到任何任务,先读 E:\AiProject\vibe-pipeline\manuals\总入口.md,再回本工程干活。`
3. 之后对该工程说的每一句话,AI 都会按五步工作流执行:需求 → 规划 → 白盒 → 资产精修 → 实机验收。
