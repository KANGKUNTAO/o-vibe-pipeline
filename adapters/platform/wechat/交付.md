# 平台交付手册 — 微信小游戏实例(M5)

> **M5 平台交付链路的第一个平台实例。** 五步工作流第 5 步(实机验收)的微信侧执行细则,配合 [manuals/验收清单.md](../../../manuals/验收清单.md) 通用条目 4/5/6/7/8 与本目录 [验收附录.md](验收附录.md) 使用。
> 操作工具见 `adapters/cocos/引擎操作.md`(构建/检查/审计/DevTools 工具组)。
> 状态:框架版(2026-09-29);提审材料清单在 001 走到交付时按当期规则补全。

## 交付前检查链(顺序执行,任何一环不过就修完重来)

1. `cocos_local_create_wechat_build_config` — startScenePath + designResolution(手机适配,如 720×1280 fitWidth)
2. `cocos_local_build_wechatgame` — 命令行构建(成功返回 exit 36,以工具 JSON 为准)
3. `cocos_local_check_wechat_build_output` — 产物必备文件 + 包体预警
4. `cocos_local_audit_runtime_package` — 静态审计:大纹理/大音频/首包风险
5. DevTools(需先安装微信开发者工具并配 `WECHAT_DEVTOOLS_CLI_PATH`):`open_wechat_devtools` → 模拟器/真机预览
6. `cocos_local_collect_runtime_evidence` — 汇总证据,对齐"运行时已验证"口径
7. 对照《验收清单》8 条逐项打勾,证据入 `evidence/`

## 包体预算(主包 ≤4MB 的分配建议)

| 槽位 | 预算 | 说明 |
|---|---|---|
| 引擎+代码 | ~1.5MB | 精简模块,按需裁剪引擎特性 |
| 首场景资源 | ~1.5MB | 启动即用:loading 图/首界面/音效开关 |
| 系统与配置 | ~0.5MB | 八件套首启必需部分 |
| 余量 | ~0.5MB | 给增长留头寸 |

其余资源全部进分包或远程资源(远程资源注意:微信要求资源走已备案域名 + https)。**整包上限以开工时核实的当期规则为准**,结论记立项卡附录。

## 性能质检口径

- 机型:立项卡指定(取当期微信用户主流档位的中端机)
- 场景:核心玩法连续 5 分钟 + 连续切 10 个界面
- 指标:帧率不低于立项卡下限;内存不超当期微信红线(核实后记立项卡);无肉眼可见卡顿尖峰
- 证据:性能面板录屏或数据导出

## 提审材料清单(交付期按当期规则补全,先立框架)

- [ ] 隐私协议页面 + 首启授权流程(可同意/可拒绝)
- [ ] 用户信息收集项与隐私声明一致(检查 SDK 上报)
- [ ] 类目资质(游戏类目所需材料)
- [ ] 健康系统(如当期规则要求)
- [ ] 版号:仅内购变现需要;**纯广告免**——变现模式立项卡已定,此处只核执行
- [ ] 域名备案:请求过的所有远程域名(含资源 CDN)
- [ ] 提审包通过微信开发者工具「上传」预检

## 埋点交付(验收清单第 8 条)

- 《埋点字典》放 `docs/埋点字典.md`:事件名、触发时机、参数、对应分析目的
- 最小事件集见《验收清单》第 8 条;真机触发后后台可见才算数

## 红线

- 本管线**不上传、不提审**(引擎操作工具的边界):上传与提审由用户在微信后台亲自执行,AI 只备齐材料与预检结论。
- appid/密钥只在环境变量与本地配置,绝不入库。
