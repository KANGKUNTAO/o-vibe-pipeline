# 引擎操作手册 — AI 操作 Cocos Creator(MCP 通道)

> 本手册是 AI 在本管线下操作 Cocos Creator 的**唯一通道说明**。任何"打开编辑器、改场景、放素材、构建微信包"的动作都走 MCP 工具 `cocos_creator_local`,不手工点编辑器、不直接改场景文件。
> 分工:本册教**怎么操作编辑器与构建**;写代码的纪律见 `manuals/代码生成.md`(分层契约)与本目录 `引擎上下文.md`(API 纪律与版本基线)。

## 通道架构(三层)

```

       └─ 编辑器桥 extensions/codex-editor-bridge(HTTP 127.0.0.1:17388)
            └─ Cocos Creator 3.8.8 编辑器(场景/AssetDB 真实状态)
```

- **游戏工程接入**:工程 `.zcode/config.json` 里已配 `cocos_creator_local`(带 `COCOS_CREATOR_PATH` 环境变量)。新游戏工程照抄 001 号(`E:\AiProject\Vibe-OFrame\.zcode\config.json`)。
- **编辑器桥**:每个游戏工程装一次(`cocos_local_install_editor_bridge`),装到 `<工程>/extensions/codex-editor-bridge/`,编辑器打开工程后自动监听 17388 端口。

## Windows 注意事项(必读)

1. **路径传参一律用正斜杠**:`E:/AiProject/xxx`;JSON 里反斜杠会被 Git Bash 转义踩坑。
2. `creatorPath` 已由环境变量 `COCOS_CREATOR_PATH` 提供,**工具调用不必再传**;若环境变量失效,手动传参兜底。
3. 微信开发者工具 CLI 同理:环境变量名 `WECHAT_DEVTOOLS_CLI_PATH`,装好后配进工程的 `.zcode/config.json`。
4. **命令行构建成功时 Cocos 返回 exit code 36**(官方行为,不是失败)。判断成败看工具返回的 JSON,不要只看退出码。

## 工具速查(按职能分组)

**环境与项目**
- `cocos_local_get_environment` 检测本机 Creator / DevTools 路径
- `cocos_local_create_project` 从内置模板建 3.8 工程
- `cocos_local_open_project` 启动/复用编辑器打开工程(`waitForBridge: true` 等桥就绪)
- `cocos_local_inspect_project` 体检:目录/设置/场景/脚本/桥/构建产物

**脚本与骨架**
- `cocos_local_create_component_script` 建 TypeScript 组件
- `cocos_local_create_minigame_skeleton` 小游戏起步脚本+场景蓝图
- `cocos_local_create_architecture_skeleton` 多系统架构起点(复杂玩法可选)

**编辑器桥与场景(核心操作面)**
- `cocos_local_install_editor_bridge` / `check_editor_bridge` / `wait_for_editor_bridge`
- `cocos_local_call_editor_bridge` 直调桥路由(逃生舱,前两个不覆盖的操作走这里)
- `cocos_local_open_scene` 在编辑器里打开场景
- `cocos_local_create_scene_from_template` 从模板建场景
- `cocos_local_apply_scene_blueprint` 应用场景蓝图(建节点/挂组件/设属性/保存)——**白盒搭场景的主力工具**
- `cocos_local_assign_sprite_frame` / `assign_sprite_frame_sequence` / `create_sprite_node` / `place_sprite_assets` 素材挂进场景(单个/逐帧序列/批量)

**微信构建与交付**
- `cocos_local_create_wechat_build_config` 写构建配置(记得传 `designResolution`,如 720×1280 fitWidth)
- `cocos_local_build_wechatgame` 命令行构建 wechatgame
- `cocos_local_check_wechat_build_output` 检查产物必备文件+包体预警
- `cocos_local_audit_runtime_package` 包体预算/大纹理/大音频/首包风险静态审计
- `cocos_local_open_wechat_devtools` / `preview_wechat_devtools` / `manage_wechat_devtools` DevTools 打开/预览/清缓存(需先装 DevTools)

**验收证据**
- `cocos_local_collect_runtime_evidence` 汇总场景/桥/构建/DevTools/截图/日志证据,给验证状态

## 标准流程:从打开工程到微信构建

1. `cocos_local_open_project`(waitForBridge)——编辑器没开就先开
2. `cocos_local_apply_scene_blueprint` 搭/改场景 → 保存
3. 素材放入:`place_sprite_assets` / `assign_sprite_frame_sequence`(素材 PNG 先写进 `assets/`,等 AssetDB 导入完再挂)
4. `cocos_local_create_wechat_build_config`(startScenePath + designResolution)
5. `cocos_local_build_wechatgame` → `check_wechat_build_output` → `audit_runtime_package`
6. 装了 DevTools 后:`open_wechat_devtools` → 真机/模拟器验证 → `collect_runtime_evidence`

## 验证口径(与《验收清单》衔接,不许混用)

| 口径 | 含义 | 对应验收清单 |
|---|---|---|
| 构建通过 | 构建完成,产物检查通过 | 第 5 条的必要非充分条件 |
| DevTools 已打开 | 开发者工具接受了构建目录 | 第 4 条的一部分 |
| 运行时已验证 | 启动/输入/核心循环/结算/重开/日志/截图证据齐全并检查过 | 第 1 条及第 5 步总验收 |

**只凭"构建通过"声称可玩,违反总入口完成规则。**

## 边界与安全

本通道只做本地开发与打包:**不上传代码、不提审、不管理 appid 密钥、不改支付/广告/登录配置、不生成素材**(素材走 M2 生成工具)。纯本地玩法检查用占位 appid;测微信 API 前换真实 appid(密钥放环境变量,绝不入库)。

构建目标当前覆盖 wechatgame(微信小游戏是平台适配层的首个实例);其他平台的构建链路随对应平台适配器(`adapters/platform/<平台>/`)引入,本手册届时补充对应工具用法。

## 已知问题与经验

- 2026-09-29:`get_environment` 在 Windows 只探测 macOS 路径(上游问题),靠环境变量解决,不影响使用。
- 编辑器桥只在"编辑器打开着该工程"时在线;编辑器关了桥就断,重开用 `open_project`。
