# 引擎上下文 — Cocos Creator 2D API 纪律

> **AI 写任何 Cocos 代码前必读本册。** 与 `引擎操作.md` 分工:那册教"怎么经 MCP 操作编辑器与构建",本册教"代码怎么写才符合引擎规律"。API 细节以官方文档为准,本册管**纪律与约定**。
> 状态:协议版(2026-09-29),随 001 实战修订。

## 版本基线声明

- 本册全部约定基于 **Cocos Creator 3.8.8,2D 项目,TypeScript**。
- Cocos 3.x 小版本之间存在 API 差异。**超出本册基线的 API 用法,先在编辑器里实测验证再依赖**;验证结论记录进游戏工程文档。不许凭印象使用未验证 API。

## 组件生命周期(用对时机)

| 回调 | 用途 | 纪律 |
|---|---|---|
| `onLoad` | 一次性初始化、获取组件引用 | 不做依赖其他组件初始化的工作 |
| `start` | 首帧前,依赖已就绪的逻辑起点 | 订阅机制事件在此做 |
| `update(dt)` | 每帧 | **不创建对象、不 find 节点、不做查找**;dt 单位是秒 |
| `onEnable` / `onDisable` | 激活态逻辑 | 反复开关的订阅在这里对称做 |
| `onDestroy` | 清理 | **on/on 必须配对 off**,否则泄漏与重复回调 |

计时用组件自带的 `schedule` 或状态机推进,不在 `update` 里手写浮点累加(漂移)。

## 坐标系与适配

- 2D 世界坐标 **y 轴向上**;UI 节点在 Canvas 下,本地坐标相对父节点**锚点**。
- 屏幕适配由**项目设置里的设计分辨率** + fitWidth/fitHeight 决定(3.x 中这是项目级设置,不在 Canvas 节点上);构建配置里的 designResolution 必须与项目设置**一致**(MCP 构建配置工具传的值要与项目设置相同),否则真机适配错位。
- 多分辨率布局禁止绝对像素摆位;用 Widget 对齐 + 父容器缩放。设计分辨率以立项卡为准(默认 720×1280 fitWidth)。
- 屏幕坐标→世界坐标用 camera 的换算接口,**不手写比例**。

## UI 结构约定(与场景蓝图工具对齐)

```
Canvas
├── Background     背景(最底,中性色/成品图)
├── GameRoot       玩法主体(棋盘/角色/实体)
├── HUD            常驻界面(分数/步数/按钮)
├── Popup          弹窗层(结算/商店/确认,带遮罩,一次一个焦点)
└── Persistent     跨场景常驻(加载态/全局提示)
```

- 每层一个节点,层级顺序即显示顺序;弹窗一律进 Popup 层,不散落。
- 触摸目标必须有足够大的 `UITransform` 命中区;小图标按钮配大热区。

## 资源与 AssetDB 纪律

- 组件引用资源用 `@property(SpriteFrame / Prefab / AudioClip)` 声明,编辑器里赋值或经 MCP 工具(`assign_sprite_frame` 等)写入;**禁止代码里硬编码路径动态加载未声明资源**。
- 真需要运行时加载:只走 `resources/` 目录 + `resources.load`,路径不带扩展名;加载失败必须有回调处理,不许裸调。
- 图片的 `SpriteFrame` 是子资源:给 Sprite 赋图要用 SpriteFrame 子资源(赋原图纹理会白块/报错)——MCP 的 `assign_sprite_frame` 已封装此细节。
- 资产文件名 = 资产 ID(manifest 契约);美术源文件不进 `assets/`(放工程外或 `raw/`,避免误导入)。

## 事件与通信

- 节点触摸/按钮:优先 Button 组件 + click 事件;自定义触摸用 `Node.on(...)`,**onDestroy 对称 off**。
- 跨模块通信:全局 EventTarget,事件名**必须是机制契约里登记的事件**(字符串常量集中定义,禁止裸字符串散落)。
- 机制层状态变化 → 广播事件 → UI 订阅刷新;UI **不轮询不猜状态**。

## 模块结构(与代码生成手册的分层对应)

```
assets/
├── scripts/
│   ├── game/        机制层:纯 TS,零节点依赖,可 Node 环境单测
│   ├── components/  绑定组件:把节点/组件接到机制层
│   ├── ui/          UI 组件:界面逻辑(面板/弹窗/HUD)
│   ├── platform/    平台适配层副本:SDK 封装,只此目录准调平台 API
│   └── lib/         工具(存档封装、常量、事件名定义)
└── components/      组件库副本(自包含 Prefab+脚本,从 adapters/cocos/组件库 拷入)
```

- 机制层(`game/`)禁止 import 展示类(Sprite/Button/Node 等);要分事件/数据类型就抽到 `lib/` 或契约文件。
- 存档:`lib/` 里单一存档模块封装 `sys.localStorage`,键名前缀 = 游戏代号;JSON + `version` 字段(迁移用);**读写只经机制层**,组件不直读直写。

## 常见坑清单(出问题先查这里)

| 症状 | 常见根因 |
|---|---|
| Sprite 显示白块 | 没赋 spriteFrame(赋成了纹理而非子资源) |
| 节点初始化没执行 | `active=false` 的节点 onLoad **推迟到首次激活**才执行;依赖时序的初始化放 start,或先激活再初始化 |
| 位置错乱 | 父子锚点坐标系混用、或设计分辨率与构建配置不一致 |
| 回调触发两次 | 事件监听没 off 就重复 on |
| 适配错位 | Widget 与绝对坐标混用;改了 Canvas 分辨率没同步构建配置 |
| 真机与预览不一致 | 用了预览环境才有的 API、或资源加载时序不同(真机更慢,要处理加载失败) |
| 包体超预算 | 未压缩纹理/音频入库;构建配置没开纹理压缩 |

## 已知平台差异(随平台适配层补全)

- 预览/浏览器环境与微信小游戏运行时的差异(包内路径、API 可用性、生命周期)由平台适配层(`platform/`)收敛,**业务代码不写平台 if/else**;新增平台行为差异登记进 `adapters/platform/<平台>/`。
